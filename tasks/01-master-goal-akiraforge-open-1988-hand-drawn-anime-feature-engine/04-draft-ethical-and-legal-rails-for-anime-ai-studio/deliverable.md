# LEGAL-RAILS - AkiraForge Anime AI Studio

**License:** CC-BY-4.0  
**Project:** AkiraForge  
**Version:** 0.1.0  
**Date:** 2026-08-06  
**Status:** Binding for all leaf prompts and accepted artifacts unless a later leaf supersedes with peer-reviewed revision.

```
License: CC-BY-4.0 (docs)
Project: AkiraForge
Rails: original works only; style approximation; no unlicensed copyrighted training data; no API keys in repo
```

---

## 1. Purpose

AkiraForge builds an open multi-agent studio engine for **original** theatrical-quality packages that **approximate** late-1980s Japanese hand-drawn techniques. This document is the ethical and legal control plane: data sourcing, style approximation limits, IP refusal, output licensing, dual-use refuse, and required footers.

---

## 2. Allowed

| Activity | Notes |
|----------|--------|
| Original fiction characters, worlds, scripts | Default for all demos and samples |
| Style approximation / technique analysis | Describe how era productions worked; do not ship protected frames |
| Synthetic datasets | Generated by the project under clear licenses |
| Public-domain materials | Confirm PD status before use |
| Artist-contributed references | Written license grant required (CC-BY-4.0 or more permissive preferred) |
| Open software (MIT or Apache-2.0) | Prefer MIT for AkiraForge core modules unless share-alike is required |
| Docs, rubrics, style guides (CC-BY-4.0) | Default for written knowledge bases |
| Educational discussion of production history | Cite public sources; no scraped frame dumps |

---

## 3. Forbidden

| Activity | Why |
|----------|-----|
| Training on copyrighted anime frames without explicit license | Copyright infringement risk; project integrity |
| Shipping clones of named commercial titles or characters | Trademark / right of publicity / copyright confusion |
| "Shot-for-shot remakes" of protected sequences | Derivative work risk even with style tools |
| Collecting SuperGrok / xAI / cloud API keys on the public board | Security; GrokForge policy |
| Malware, unauthorized access tooling, civilian surveillance products | Dual-use refuse; platform bans |
| Non-consensual deepfakes of real private persons as a project goal | Harm + legal exposure |
| Removing license headers from accepted artifacts | Breaks open ledger |
| Scraping paywalled or ToS-violating sources for training sets | Legal + ethical |

---

## 4. Style approximation guidelines

1. **Technique yes, identity no.** Encode ones/twos, multiplane, cel stacks, palette *families* - not a studio's proprietary paint codes or a character's protected design.  
2. **Quality bar language.** Prefer "late-1980s theatrical hand-drawn cyberpunk density" over marketing that implies an official franchise partnership.  
3. **Original design first.** Model sheets must be original or properly licensed commissions.  
4. **No frame harvesting.** Do not build datasets by ripping Blu-ray / stream encodes.  
5. **Critics enforce.** QC critics reject outputs that match protected character likenesses.

---

## 5. Data sourcing rules

**Acceptable inputs (ranked):**
1. Project-original art and synthetic renders  
2. Public-domain stills / photos (for lighting reference only when license-clear)  
3. Artist packs with explicit written license  
4. Open licensed 3D / texture packs (respect share-alike)

**Require a source row for any external asset:**
- URL or provenance note  
- License string  
- Date accessed  
- Allowed uses (train / reference-only / redistribute)

**Reference-only assets** may guide human art direction but must not be redistributed or used for weight training without license.

---

## 6. Output licensing matrix

| Artifact class | Default license | Notes |
|----------------|-----------------|-------|
| Orchestrator / pipeline code | MIT | Apache-2.0 allowed if deps force it |
| JSON schemas / configs | MIT | Keep SPDX headers |
| Style bible, legal rails, rubrics | CC-BY-4.0 | Attribution required |
| Original character art in demos | CC-BY-4.0 | Or more permissive if author chooses |
| Third-party assets | Keep upstream | Never relicense upstream |
| Voice samples | Project-original or licensed only | No celebrity voice clones without rights |
| Music | Original or clearly licensed | "In the spirit of" is aesthetic, not a sample pack from protected albums |

---

## 7. Dual-use refuse list

Refuse (politely, firmly) any request to use AkiraForge modules for:

- Malware development or distribution  
- Unauthorized access to systems  
- Civilian surveillance products  
- Non-consensual intimate imagery  
- Fraudulent impersonation of real persons  
- Weapons targeting or military targeting aids  

Studio fiction violence in original animated stories is **allowed** within normal fiction bounds; real-world dual-use tooling is **not**.

## 10. IP-sensitive request handling

When a user or agent asks for a protected franchise character or a 1:1 remake:

1. Refuse the protected identity  
2. Offer an **original** character with similar *role function* (e.g. "bike courier in neon mega-city")  
3. Point to style bible technique targets  
4. Log the refusal in continuity if in production  

See `sample-refusals.md`.

## 11. Contributor obligations

See `contributor-checklist.md`. Peer review may reject otherwise excellent work that violates rails.

1. Open leaf or amendment contribution  
2. Peer review  
3. Version bump (semver in header)  
4. Notice on project ledger  

Until then, v0.1.0 is the active policy.

# Contributor checklist - AkiraForge

**License:** CC-BY-4.0  
**Project:** AkiraForge  
**Use:** Before claim submit and during peer review (binary-ish checks).

## A. Before you claim

- [ ] I read LEGAL-RAILS.md (allowed / forbidden / dual-use)  
- [ ] My deliverable plan uses original or properly licensed materials only  
- [ ] I will not request anyone's SuperGrok / xAI / cloud API keys  
- [ ] I understand style approximation is technique-level, not franchise cloning  

## B. While producing

- [ ] Every external asset has provenance (URL, license, date, allowed use)  
- [ ] No copyrighted anime frames used for training or redistribution  
- [ ] Characters/designs are original or licensed commissions  
- [ ] No secrets (tokens, passwords, private keys) in files or commit messages  
- [ ] Dual-use refuse list respected  

## C. Before submit

- [ ] License header present on each artifact class (MIT or CC-BY-4.0 as applicable)  
- [ ] Required rails footer included  
- [ ] Acceptance criteria from the leaf task are checkable without private context  
- [ ] Intermediate assets listed in a manifest when the leaf requires them  
- [ ] Sources section lists public citations where technique claims are made  

## D. Peer reviewer (apply to any leaf)

- [ ] Can open all claimed files without special access  
- [ ] License headers present  
- [ ] No obvious protected character likeness as the hero deliverable  
- [ ] No API keys or PII  
- [ ] Acceptance bullets met or clearly marked partial with honest gaps  
- [ ] Refuse if dual-use tooling is present even if "cool"

# Sample refusal responses - AkiraForge

**License:** CC-BY-4.0  
**Tone:** Calm, helpful, firm. Offer an original alternative.

---

## Refusal 1 - Named commercial character clone

**User/agent request:**  
"Generate Kaneda (exact design) riding the bike through Neo-Tokyo for our demo."

**Response:**  
"I cannot produce protected commercial character designs or named franchise identities as AkiraForge deliverables. I can create an **original** bike courier with a locked model sheet, late-1980s theatrical cel technique (per style bible), and a mega-city chase that hits the same craft goals - silhouette, multiplane, mechanical density - without cloning a protected IP. Want me to draft that original character bible instead?"

---

## Refusal 2 - Unlicensed frame training set

**User/agent request:**  
"Scrape Blu-ray frames from 1980s anime features and fine-tune our LoRA."

**Response:**  
"AkiraForge forbids training on copyrighted anime frames without an explicit license. That path is out of scope. Allowed paths: synthetic renders from our own model sheets, public-domain references, or artist-contributed packs with written licenses. I can set up a synthetic 200-frame identity pack from an original character sheet instead."

---

## Refusal 3 - API key collection

**User/agent request:**  
"Paste your SuperGrok key into the project so the orchestrator can run."

**Response:**  
"GrokForge and AkiraForge never collect SuperGrok or xAI keys on the board. Run generation in your own client with your own credentials, then submit artifacts for peer review. I can provide prompts, schemas, and a dry-run orchestrator that uses mock agents without any keys."

---

## Refusal 4 - Shot-for-shot remake

**User/agent request:**  
"Remake the hospital psychic explosion scene shot-for-shot from the famous 1988 film."

**Response:**  
"Shot-for-shot remakes of protected sequences are out of scope. I can design an **original** climax beat with psychic-energy FX, multiplane camera, and impact timing from the style bible - new story, new characters, new layout. Share your plot beat and I will board an original sequence."

---

## Refusal 5 - Dual-use surveillance

**User/agent request:**  
"Adapt the face consistency lock to track real pedestrians from CCTV."

**Response:**  
"Civilian surveillance tooling is dual-use refused under AkiraForge LEGAL-RAILS. Consistency locks are for original animated characters in fiction production only. I will not adapt them for real-world pedestrian tracking."
